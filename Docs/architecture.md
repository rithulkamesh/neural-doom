# Replaceable Doom core

The native shell owns the window, event collection, monotonic scheduling, local file access, Metal submission, and presentation. Those are host responsibilities. The destination is a **composable network of exact frozen circuit modules** over bounded state arrays, scheduled explicitly, until no DoomGeneric gameplay or renderer code executes. The current baseline is an executable specification and parity oracle.

## Current boundary

`Sources/DoomCore/g_game.c` is the sole patched gameplay adapter. It captures a 24-cell `HMMovementInput` before mouse consumption, lets the original `G_BuildTiccmd` compute its C reference, and calls `HM_EvaluateMovement` before the ticker. On supported input, the Metal result replaces `forwardmove`, `sidemove`, `angleturn`, and the carried `turnheld`. C is committed only on domain rejection, Metal failure or the 2 ms deadline, or parity mismatch. Eight preallocated input/output slot pairs isolate late Metal commands; a timed-out command cannot overwrite the next tic’s buffers. `Sources/Bridge/MovementABI.h` is the stable C-facing version 1 command ABI; Swift and UI code do not read DoomGeneric gameplay globals. The 178 live-operation graph, operation IDs, edges, layer IDs, roots, and 7 table entries are generated by `CircuitGraph` and recorded in `locomotion-graph.json` (graph hash `05cb2b70f251c2fe`). The manifest is checked by the test executable.

The engine queue is the single owner of reference C state. `singletics` makes each `HM_EngineFrame` execute one command and one simulation tic; `TicScheduler` may issue several such calls between two MTKView presentations. The same input snapshot reaches C and Metal; C consumes mouse state once after capture. A dedicated Metal-attempt queue keeps command creation and encoding off the engine queue; the engine waits at most until the tic's 2 ms attempt deadline before committing C. A late worker result is discarded and its preallocated buffer slot stays isolated until completion. An OS scheduling pause can still overshoot a wall-clock deadline, so pacing is measured in real play traces. The inspector's pause stops calls at tic boundaries, step issues one call, and resume resets the scheduler wall-clock baseline. The panel reads sampled results from the live circuit. Off mode allocates no operation-value trace; on mode samples once every four tics into a 128-entry drop-oldest ring. Attempt latency includes worker dispatch and Metal submit/wait; layer values are CPU replay data, **not** per-layer GPU time.

The current exact domain is binary buttons, joystick axes -1/0/1, mouse X -256…256, mouse Y -8192…8192, `ticdup` 1…4, and incoming `turnheld` 0…16,777,212. The circuit uses FP32 exact integers under these bounds with ordered affine, ReGLU, and index-read instructions; Metal compiles with safe math. Domain validation runs before GPU dispatch. Out-of-domain values never index circuit tables. The input ABI's reserved cell is ignored in this version.

## CircuitModuleV1 destination ABI

`Sources/Bridge/CircuitModuleABI.h` encodes the version 1 envelope. Each future module receives an immutable `HMModuleInputV1` with schema version, tic ID, source hash, bounded typed input/state spans, read-only WAD table handles, and explicit capacity metadata. It returns `HMModuleResultV1` with status (`exact`, `unsupported-domain`, `capacity-exceeded`, `execution-error`, `parity-mismatch`), bounded state-delta arrays, event arrays, and output spans. A sampled trace token is scheduler metadata rather than a gameplay output. Module output is staged, validated, then committed by `CircuitScheduler`; a failed module cannot partly mutate the world. State-cell IDs, operation IDs, layer IDs, and table IDs are stable within a manifest version. Changes that alter meaning require a new ABI/manifest version, not silent reinterpretation.

During migration, each module ledger entry is one of `reference-C`, `dual-run`, or `circuit-owned`. `reference-C` owns state; `dual-run` commits C and compares a circuit candidate; `circuit-owned` commits exact circuit output while C remains an optional oracle/fallback. The current locomotion entry is circuit-owned; reference C remains the explicit safety path. Ownership is per module and per state cell, so no app feature may depend on an unversioned DoomGeneric global. `Docs/circuit-coverage.json` is the machine-readable ledger. Its current 1/10 is a count of enumerated core modules, **not** instruction coverage.

## WAD-to-circuit memory and capacity policy

The host parses an IWAD/PWAD directory and decodes map lumps into versioned bounded tables: vertices, linedefs, sidedefs, sectors, nodes, subsectors, segs, things, blockmap, textures, flats, and sprite metadata. Table handles and per-map lengths are inputs to circuit modules; the application does not bake one level into weights or shader code. A loader checks lump bounds and map-derived capacities before a level commits. Maps fitting a module's declared limits use exact circuit memory/index reads. While the reference exists, overflow or unsupported features select reference C for the affected module/tic and increment visible counters. After reference removal, unsupported content yields a clear load error; it never truncates arrays or silently approximates behavior. Capacity limits and maximum observed occupancy are manifest fields and become acceptance tests for each migrated module.

The scheduler order is input normalization → tic commands → player movement and collision → interactions/combat → thinker/AI transitions → world commit → HUD/automap → BSP traversal → tiled rasterization → host presentation. Modules exchange bounded state and event arrays, including explicit sound, spawn, pickup, and sector-change events. Deterministic RNG state is a circuit cell. The host submits circuit kernels and presents pixels, but it does not reimplement rules. Migration gates require generated C-vs-circuit snapshots, WAD-backed traces, exact outputs and state deltas, capacity tests, and measured latency/frame pacing. Once all ledger entries are circuit-owned, remove `Sources/DoomCore` from the application target and confirm a reference-free build and play trace.

## Staged ledger

1. **Tic commands:** current locomotion circuit; next move all remaining command fields and low-res turn carry.
2. **Movement and collision:** bounded blockmap candidates, fixed-point thrust, position and crossed-special events.
3. **Doors, switches, items, combat, projectiles:** pure transitions plus explicit side effects.
4. **Thinker scheduler and monster AI:** bounded thinker slots, deterministic ordering/RNG, state transitions.
5. **World state:** circuit-owned player/sector/thing arrays, map transitions and save state.
6. **HUD and automap:** exact state decisions and drawing.
7. **BSP traversal:** bounded visibility queues and clipping.
8. **Tiled rasterization:** exact palette and pixel output in tile circuits.
9. **Remove reference C loop:** `CircuitScheduler` owns all core sequencing; a reference-free app target runs every accepted WAD.

The ledger's stage numbers split the interactions and final loop for auditability; `Docs/circuit-coverage.json` is the authoritative module list and status.
